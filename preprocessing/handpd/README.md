# NewHandPD 전처리

스마트펜 6채널 시계열을 PatchTST 입력용 `[N, 6, T]` 배열로 만든다.
음성 전처리(`preprocessing/voice/`)와 **같은 형태**로 맞춰, 공유 인코더가 두 모달을
동일한 코드로 받을 수 있게 한다.

```
필기  [N,  6, 2000]   ← 6채널(펜 센서), 2초 × 1000Hz
음성  [N, 64,  126]   ← 64채널(멜 밴드), 126 프레임
```

---

## 사용법

```bash
# 1) 윈도우 생성
python preprocessing/handpd/preprocess.py --data-root dataset/handpd --seconds 2

# 2) 분할 검증 + 나이 교란 진단
python preprocessing/handpd/split.py --npz dataset/handpd/windows_2s.npz \
    --data-root dataset/handpd
```

`dataset/handpd/` 아래에 원본이 이렇게 있어야 한다. **데이터는 git에 올리지 않는다.**

```
dataset/handpd/
├── HealthySignal/*.txt
└── PatientSignal/*.txt
```

### 산출물

`dataset/handpd/windows_2s.npz`

| 키 | shape | 내용 |
|---|---|---|
| `X` | [N, 6, T] float32 | **raw 윈도우** (정규화 안 됨) |
| `y` | [N] | 0=정상, 1=환자 |
| `subject_id` | [N] | `"H_12"` / `"P_7"` — 분할 키 |
| `task` | [N] | circle / spiral / meander / diadochokinesis |

## 데이터 개요

| 항목 | 값 |
|---|---|
| 파일 | 792개 (6채널, 1000Hz) |
| 피험자 | **61명** (정상 35 / 환자 26) |
| 총 샘플 | 약 1,470만 |
| 2초 윈도우 | 13,474개 (정상 4,867 / 환자 8,607) |
| 나이 | 정상 43.4세 / 환자 58.0세 |

### 6채널

`ch1` 마이크 · `ch2` 그립력 · `ch3` 펜촉 축압력 · `ch4~6` 기울기 X/Y/Z

**x·y 좌표(궤적)는 없다.** "펜이 어디를 지나갔나"가 아니라 "어떻게 쥐고 눌렀나"를
재는 신호다. 채널 해상도를 실측하면 `ch1~3`은 매 샘플 값이 바뀌지만(100% 고유값),
`ch4~6`은 계단형으로 73%가 이전 값을 유지한다. 미세한 떨림은 주로 `ch1~3`이 담는다.

## 설계 결정과 근거

### subject_id는 파일명이 아니라 `Person_ID_Number`로

파일명 번호(`-H1`~`-H38`, `-P1`~`-P32`)는 66개지만 **실제 피험자는 61명**이다.
환자군에 같은 사람이 다른 번호로 들어가 있다.

| 실제 동일인 | 파일 번호 |
|---|---|
| 환자 A | `P1` = `P4` |
| 환자 B | `P9` = `P10` |
| 환자 C | `P15` = `P17` |
| 환자 D | `P2` = `P25` = `P26` |

파일명으로 분할하면 `P2`는 train, `P25`는 test에 갈 수 있는데 **둘이 같은 사람**이다.
모델이 그 사람의 손버릇을 외워서 test를 맞히므로 정확도가 가짜로 부풀어 오른다.
(정상군은 전수 확인 결과 중복 없음)

### 앞 2행 제거

각 파일 첫 1~2샘플에서 그립·압력이 정상 범위(약 5)에서 **200대로 튄다.**
2번째 샘플부터 바로 복귀하므로 손 움직임이 아니라 센서 초기화 잡음이다.

### 이상치를 자동 제외하지 않는다

파일 길이가 3~106초로 편차가 크다. 가장 긴 `circA-P13`(106초)을 확인하면

- 6채널 동시 정지 구간 **0샘플**
- 압력이 106초 내내 유지 (펜을 떼지 않음)
- 이미지로 봐도 선을 여러 번 덧그림

즉 센서 오류가 아니라 **실제로 느리게 그린 것**이며, 서동증(bradykinesia)의 직접
증거다. 자동 필터를 걸면 질병 신호가 가장 뚜렷한 샘플을 버리게 된다.
그래서 리포트만 출력하고 판단은 사람이 한다. **제외 0개.**

### 윈도우 2초 · 50% 겹침

트랜스포머는 고정 길이 입력이 필요한데 파일이 3~106초로 제각각이다.

| 방법 | 문제 |
|---|---|
| 최대 길이로 패딩 | 짧은 파일 대부분이 빈 값 |
| 최소 길이로 자르기 | 긴 파일 대부분 버림 → **서동증 신호 손실** |
| **윈도잉** | 손실 0, 샘플 수 증가 |

길이는 1/2/4초를 실제로 비교해 정했다.

| 윈도우 | 개수 | 피험자 정확도(RF) |
|---|---|---|
| 1초 | 28,144 | 85.1% |
| **2초** | **13,474** | **90.1%** |
| 4초 | 6,136 | 87.1% |

서동증은 "느림" 자체가 신호라 1초보다 긴 맥락이 필요하지만, 4초로 늘리면 윈도우가
6,136개로 줄어 데이터 부족이 맥락 이득을 잡아먹는다. **2초가 균형점.**

겹침은 획이 윈도우 경계에서 두 동강 나는 것을 막는다. 다만 이웃 윈도우만
이어줄 뿐 전체 그림의 장거리 흐름은 살리지 못하므로, 그건 윈도우 길이로 조절한다.

### 정규화를 npz에 넣지 않는 이유

채널마다 값 범위가 다르므로(마이크 −1~6, 압력 0~11) z-score가 필요하다.
**그러나 통계를 전체 데이터로 내면 test 정보가 train으로 새어든다.**

→ npz에는 raw를 저장하고, 정규화는 **분할 후 train fold 통계로만** 적용한다.
`fit_channel_stats()`는 float64로 누적하는데, 마이크 채널이 값 3.0 근처에 몰려
분산이 작아 float32로 2,800만 개를 합산하면 오차가 커지기 때문이다(실제로 겪음).

## ⚠️ 이 데이터를 쓸 때 주의할 것

### 피험자 61명 — 1명이 1.6%p

fold당 test가 12~13명이라 **한 명 오분류가 1.6%p**를 움직인다.
seed만 바꿔도 정확도가 **평균 5.8%p, 최대 11.5%p** 흔들린다.

실제 사례: 같은 설정이 seed 42에서 91.7%, seed 7에서 80.4%가 나왔다.
단일 seed로 "90% 돌파"라고 보고했다면 재현되지 않았을 것이다.

> **결과는 seed 3개 이상의 평균 ± 표준편차로 보고할 것.**

### 나이 교란

정상 43.4세 vs 환자 58.0세로 **14.6세 차이**다. 모델이 병을 배운 것인지 나이를
배운 것인지 구분되지 않으므로, `split.py`가 fold마다 나이-only 로지스틱 회귀
베이스라인을 함께 출력한다.

```
모델 정확도 − 나이-only 정확도 = 나이 위에 얹은 순수 질병 기여분
```

fold마다 나이차가 5.2~27.0세로 크게 달라 **평균이 아니라 fold별로** 봐야 한다.
나이차 8세 미만인 fold가 가장 정직한 조건이다.
